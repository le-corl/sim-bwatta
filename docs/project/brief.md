## 콘셉트

### 한 문장

원할 때 휴지 걸이를 돌리다 나타나는 작은 행동 미션을 수행하고, 휴지를 전부 낭비한 보상으로 황당한 휴지심을 모으는 로컬 미니게임.

### 의도와 사용자 경험

- 짧은 행동 미션에 집중하고 완료했다는 감각을 준다.
- 귀여운 연출 위에 `휴지를 낭비해야 할 일을 얻는다`는 킹받는 모순과 예상 밖 결과를 얹는다.
- 한 번의 시도에서 행동 미션이 1~2회 등장하며 현재 설정의 기대 횟수는 1.13회다.
- 현재 설정의 기대 런타임은 약 2분 25초다. 이는 최대 시간이 아니라 여러 판의 평균 목표다.
- 행동 미션 1회의 목표 평균은 90초, 휴지 돌리기·화면 전환의 판당 목표 평균은 합계 43초다.
- 하루 총량을 막는 명시적 횟수 제한은 두지 않는다. 최초 2회는 연속 플레이하고 이후 `5분 → 30분 → 2시간 → 5시간` 단계형 리필 간격을 적용하며, 완료한 휴지심만 로컬에 쌓는다.

### 핵심 루프

| 구간 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1. 휴지 돌리기 | 화면의 휴지 롤 또는 걸이를 반복해서 돌린다. | 휴지가 줄어들며 귀엽고 약간 얄미운 반응이 나온다. |
| 2. 행동 미션 | 중간에 멈춘 휴지에 적힌 작은 미션을 수행하고 완료를 누른다. | 1회는 보장하고, 두 번째 미션은 현재 13% 확률로 등장한다. 완료하면 휴지 돌리기로 복귀한다. |
| 3. 휴지심 보상 | 휴지를 끝까지 푼다. | 미션 1회면 일반 랜덤 휴지심, 2회면 황금 휴지심이 나타나고 로컬 보관함에 저장된다. |

휴지심 결과 카드는 이미지로 저장·공유할 수 있고, 휴지심 보관함에서 다시 확인한다.

### 휴지 돌리기 UX 제약

- 한 손 조작: 화면 아래쪽의 넓은 휴지 영역 어디서든 아래 방향 스와이프를 시작할 수 있다.
- 비가역성: 아래 방향 이동만 진행률에 더하고 위 방향 이동은 무시한다. 휴지는 절대로 되감기지 않는다.
- 조작 보정: 대각선 이동과 손가락의 좌우 흔들림은 허용하고, 세로 아래 방향 성분을 진행으로 인정한다. 작은 떨림은 무시한다.
- 가속도: 같은 거리라도 빠른 스와이프가 더 큰 진행량과 더 빠른 롤 회전 연출을 만든다. 가속 배율은 상한을 둬 우발적인 한 번의 입력으로 전부 풀리지 않게 한다.
- 입력 설정은 `swipeWeight`와 `swipeAcceleration`을 분리한다. 전자는 이동거리 전체의 기본 감도, 후자는 빠른 스와이프에 붙는 추가 배율과 상한을 조절하며 현재 튜닝값은 각각 55와 87이다.
- 상태 중단: 미션 지점에 도달하면 초과 입력을 버리고 정확히 해당 지점에서 멈춘다. 미션 완료 후 그 진행률에서 이어간다.

### 시각 구도

- 플레이 화면의 두루말이 휴지는 앞으로 늘어진 종이가 롤 몸통 대부분을 덮고, 오른쪽 원형 단면과 중앙 구멍·걸이 축만 드러나는 일반적인 휴지 걸이 구도로 표현한다.
- 플레이 휴지 롤과 아래로 풀리는 휴지의 폭은 같게 맞춘다. 휴지 칸의 절취선 간격은 넓혀 한 칸이 분명하게 보이게 한다.
- 롤은 양 끝 단면을 모두 노출한 독립 원통처럼 보이지 않게 한다. 종이 앞면을 최상단에 겹치고 오른쪽 단면만 강조해 벽걸이 휴지의 방향을 분명히 한다.
- 오른쪽 단면은 별도 타원처럼 이격되지 않게 롤 몸통의 위·아래 직선 윤곽이 타원의 위·아래 접점까지 이어져야 한다. 몸통 왼쪽 시작부만 종이가 감긴 곡률을 허용하고 오른쪽 모서리에는 곡률을 적용하지 않는다. 단면 구멍·걸이 축·오른쪽 세로 고정가이드는 같은 중심축에 정렬한다.
- 0%의 새 롤 외경은 아래로 풀리는 휴지 폭과 같은 크기로 시작한다. 롤이 풀릴수록 폭은 유지하고 외경만 실제 비율인 `새 롤 11cm : 휴지심 4cm`에 맞춰 100%에서 약 36.4%까지 눈에 띄게 줄인다. 회전 속도는 옆면의 종이 결 이동으로 보여준다.
- 풀린 휴지가 내려오기 시작하는 접선은 축 중심 `(0,0)` 기준 정면의 `x=1` 지점으로 해석해 화면상 축 높이에 고정한다. 시작점은 롤 외경 축소에 따라 위아래로 이동하지 않는다.
- 풀린 휴지의 오른쪽 세로 경계는 오른쪽 단면 타원의 중심선이 아니라 왼쪽 접점에서 아래로 곧게 이어진다. 단면 아래에 종이가 반쪽만 걸친 듯한 돌출을 남기지 않는다.
- 롤 회전, 몸통과 내려오는 휴지의 무늬 이동, 보이는 휴지 길이는 실제 반영된 진행률 하나에서 계산한다. 체크포인트에서 버린 초과 스와이프가 회전 애니메이션을 앞서게 하지 않는다.
- 전체 진행률 동안 지나가는 휴지 칸 수와 롤 회전 수는 별도 시각값으로 조절한다. 빠른 스와이프일수록 칸의 이동 전환을 짧게 하고 절취선 뒤에 짧은 잔상을 더하되, 위치의 기준은 실제 반영된 진행률에서 벗어나지 않는다.
- 풀린 휴지의 밑단은 절취선 이동량과 같은 거리만큼 실제로 아래로 늘어나며 플레이 카드 하단에서 잘린다. 하단 조작 안내보다 뒤에 배치해 휴지가 안내 오버레이 뒤로 지나가는 것이 보여야 한다. `↓ 아래로` 문구는 휴지와 분리하고 기존 170~300px 이동 범위만 유지한다.
- 첫 완료 기록이 없는 플레이에는 돌발 휴지 칸을 1회 보장한다. 이후에는 직전 완료 판에 돌발 칸이 있었다면 한 판 쉬고, 그 외 판에서 35% 확률로 등장한다. 등장 위치와 콘텐츠는 라운드 시작 때 한 번 무작위로 결정하며 미션 체크포인트와 88% 이후 완료 구간을 피한다.
- 돌발 칸은 팝업이나 정지 없이 휴지와 함께 지나가는 1~4글자 도장·단순 낙서로 표현한다. 돌발 칸 발생 여부만 완료 기록에 선택 필드로 저장하고 진행 중에는 저장하지 않는다. 첫 판 도중 종료하면 다음 시도도 첫 판 보장을 받는다.
- 바깥쪽 종이를 아래로 당기는 구도이므로 오른쪽 단면의 회전 표식은 반시계방향으로 돈다.
- 종료 직전에는 흰 종이층이 충분히 사라져 갈색 휴지심이 드러나야 한다. 99% 화면이 아직 두꺼운 흰 롤처럼 보여 완료가 갑작스럽게 느껴지지 않게 한다.
- 100%에 도달하면 결과 팝업을 즉시 띄우지 않는다. 입력을 잠근 뒤 풀린 휴지가 휴지심에서 분리되어 아래로 떨어지고, 드러난 휴지심이 짧게 튀는 완료 연출이 끝난 다음 결과 팝업을 표시한다.
- 롤·풀린 휴지의 전체 폭, 입력 민감도, 왼쪽 단면 곡률, 종이가 풀리기 시작하는 각도는 한 시각 설정 파일에서 조절한다. 시작각 0도는 축 중심의 정면 접점이며 양수는 시작점을 위쪽으로 이동시킨다.
- 롤 왼쪽 윤곽은 오른쪽 단면과 같은 원근 없는 타원의 반쪽으로 읽혀야 한다. 오른쪽 접합부는 직선을 유지한다.
- 결과 팝업의 휴지심은 세로로 선 갈색·황금색 원통으로 표현한다. 위쪽 타원면과 몸통을 가로지르는 굽은 이음선을 보여주고, 황당한 결과 문구는 원통 몸통에 직접 적는다.
- 메인의 보관함 목록은 한 줄로 풀린 두루마리 휴지 배경과 절취선으로 각 기록이 이어져 보이게 한다. 빈 상태·목록 아이콘도 위쪽 타원면과 굽은 이음선이 있는 세로 휴지심으로 통일한다.

### 행동 미션 UX

- 미션 진입과 동시에 90초 가이드 타이머를 시작한다.
- 시간은 강제 성공 조건이 아니다. 사용자는 행동을 실제로 끝냈다면 90초 전에도 완료할 수 있다.
- 90초가 지나면 실패시키지 않고 `충분해요` 상태로 바꾸며 완료 버튼을 유지한다.
- 미션 완료 후 타이머를 정리하고, 멈췄던 휴지 진행률에서 즉시 복귀한다.
- 행동 미션과 휴지심 결과 문구는 각각 독립 콘텐츠 파일에서 관리하며 MVP 기준 15개씩 제공한다.

### 화면과 저장 정책

- 화면은 `메인(휴지심 보관함)`과 `플레이` 두 개만 사용한다.
- 앱 진입점은 메인이다. 메인에서 새 플레이를 시작하고, 플레이 완료 후 휴지심 보관함으로 돌아간다.
- 같은 실행 세션에서 손을 떼거나 미션으로 중단된 진행률은 메모리에 유지한다.
- 플레이 도중에는 진행률·미션·타이머를 영구 저장하지 않는다. 앱 종료·WebView 재생성·새로고침 시 해당 회차는 처음부터 시작한다.
- 휴지가 100% 풀리고 휴지심 결과가 결정되는 `플레이 완료` 순간에만 결과를 `Storage`에 자동 저장한다.
- 결과 팝업에서 앱을 종료해도 완료 결과는 이미 보관함에 저장된 상태여야 한다.

### 메인 화면 확정 구성

- 필수: 가장 강한 기본 동작인 `새 휴지 풀기` 버튼.
- 필수: 최신순 휴지심 보관함. 휴지심을 누르면 별도 화면이 아닌 바텀시트로 문구·날짜·이미지 저장/공유를 제공한다.
- 필수: 기록이 없을 때 플레이 방법으로 연결하는 인라인 빈 상태.
- 권장: `총 휴지심 수 / 황금 휴지심 수` 두 개만 작은 요약으로 표시하고 각 라벨 옆에 일반·황금 휴지심 아이콘을 둔다.
- 권장: `이 기기에만 저장돼요` 안내를 보관함 제목 아래 비고정 보조 문구로 한 번 표시한다.
- 제외: 캘린더, 검색·필터, 연속 출석, 통계 대시보드, 설정 화면, 별도 온보딩 화면.

### 확률과 보상

| 결과 | 확률 | 미션 횟수 | 휴지심 |
|---|---:|---:|---|
| 일반 판 | 87% | 1회 | 일반 랜덤 휴지심 |
| 특별 판 | 13% | 2회 | 황금 휴지심 + 특별 등장 연출 |

`0.87 × 1 + 0.13 × 2 = 1.13`이므로 판당 행동 미션 기대 횟수는 1.13회다. 황금 휴지심은 추가 재화나 우위를 주지 않는 수집·연출 보상으로 한정한다.

### 시간 예산

| 판 | 확률 | 계산 | 목표 런타임 |
|---|---:|---|---:|
| 미션 1회 | 87% | `90초 + 43초` | 약 2분 13초 |
| 미션 2회 | 13% | `180초 + 43초` | 약 3분 43초 |
| 기대값 | 100% | `90초 × 1.13회 + 43초` | 약 2분 25초 |

3분은 개별 판의 제한이 아니라 기대 런타임 기준이다. 황금 휴지심 판은 3분을 넘길 수 있다.

| 포함 | 제외 |
|---|---|
| 휴지 풀기 인터랙션과 완료 연출 | 로그인·서버·클라우드 동기화 |
| 명시적 일일 횟수 제한 없이 단계형 리필 간격을 둔 반복 플레이 | 리더보드·친구 경쟁·리워드 |
| 판마다 행동 미션 1~2회와 완료 후 복귀 | 결제·광고·푸시 |
| 일반·황금 랜덤 휴지심과 로컬 보관함 | 장기 성장 시스템·복잡한 수집 도감 |
| 결과 카드 PNG 저장, 공유 진입점 | 서버에서 생성하는 동적 공유 이미지 |

### 기술 결정

- WebView + React + TypeScript를 사용한다. 단순 2D 인터랙션, Canvas 이미지 생성, 로컬 저장에 적합하고 React Native보다 마감 내 구현 위험이 낮다.
- 신규 프로젝트에는 최신 안정판 Apps in Toss WebView SDK 3.1.1을 사용한다. 2026-03-23부터 업로드가 막힌 SDK 1.x는 사용하지 않는다.
- 공식 CLI가 생성한 `apps-in-toss.config.ts`와 `ait build` 방식을 따른다.
- 사용자 데이터는 `@apps-in-toss/web-framework`의 `Storage`에 저장한다. IndexedDB는 iOS에서 장기 미사용 시 자동 삭제될 수 있어 핵심 기록 저장소로 쓰지 않는다.
- 결과 카드는 Canvas로 PNG를 만들고 SDK 3.1.1의 `File.saveBase64`로 기기에 저장한다. `Share.sendMessage`는 메시지 전용이므로 직접 이미지 첨부는 제외하고, 저장한 PNG와 별도로 결과 문구·앱 링크를 공유한다.
- 서버는 사용하지 않는다. 앱 삭제 시 보관함이 초기화될 수 있지만 로컬 MVP에서는 허용한다.

### 작업 방식

- 제출 완성을 최우선으로 한다.
- 학습 설명은 사용자가 그때그때 요청할 때 제공한다.

### 개발 QA 도구와 돌발 칸 동기화

- PC 개발 빌드의 메인 화면에만 로컬 완료 기록 초기화 버튼을 제공한다. 배포 빌드에는 노출하지 않는다.
- 초기화 후 다음 플레이는 완료 기록 0개인 최초 플레이로 판정한다.
- 돌발 휴지 칸은 절취선과 별도 위치 전환을 사용하지 않고, 같은 휴지 이동 레이어의 단일 transform을 공유한다. 빠르게 지나쳐도 별도 감속하지 않는다.

## 출시 전·후 업데이트 후보

### 재방문 리필 루프 — 구현 완료·공개 검증 대기

- 목적: 짧은 핵심 경험을 한 번에 과소비해 질리는 것을 막고, 다음 방문 시점을 예측 가능하게 학습시킨다.
- 사용자 플레이 테스트에서 행동 미션을 최대한 수행해도 실제 한 회차가 2분 미만이었다. 따라서 `하루 3롤 전량 지급 후 다음 날까지 차단`하는 기존 추천안은 폐기한다.
- 확정 방향: 처음 2회는 쿨다운 없이 연속 플레이를 허용하고, 2회 완료 이후부터 완료할 때마다 순차적인 시간 간격을 둔다.
- 확정 간격은 2회 완료 후 `5분`, 3회 완료 후 `30분`, 4회 완료 후 `2시간`, 5회 완료 후 `5시간`이다.
- 같은 날 추가 완료에는 `5시간`을 상한으로 반복 적용하고, 단계는 매일 현지 시각 `06:00`에 초기화한다.
- 완료한 회차만 단계를 진행시키며 중도 종료는 소비·쿨다운 대상에서 제외한다.
- 제한 중에도 휴지심 보관함과 상세·저장·공유는 사용할 수 있다. 새 플레이 CTA만 리필 상태와 남은 시간을 보여준다.
- 제한 문구 예시: `두루마리 휴지를 리필하고 있어요` / `오후 3:40에 다시 봐요 · 29분 남음`.
- 절대 시각과 남은 시간을 함께 표시해 사용자가 다음 방문 시점을 계산하지 않게 한다.
- 두 판 합계 5분은 목표 관찰값으로만 두고, 시간을 채우기 위해 스와이프나 미션을 인위적으로 늘리지는 않는다.
- 제품의 초기 습관 목표는 보편적인 `3일 습관 완성`이 아니라 `설치 후 3일 연속 재방문`으로 정의한다.

### 장기 재방문 설계 원칙

- 단계형 쿨다운은 콘텐츠 과소비를 막는 페이싱 장치다. 쿨다운 자체를 장기 리텐션 보상으로 취급하지 않는다.
- `3일 연속 재방문`은 내부 온보딩 성과 지표로 먼저 사용한다. 사용자가 하루를 놓쳤을 때 실패·초기화를 강조하는 강한 스트릭 UI는 별도 검증 없이 추가하지 않는다.
- 장기적으로는 쿨다운을 대체하기보다 날짜별 기대를 추가한다. 추천 구조는 첫날 핵심 경험 이해, 둘째 날 새 콘텐츠 기대, 셋째 날 첫 수집 이정표다.
- 날짜별 기대는 특정 결과를 고정 지급하기보다 미발견 콘텐츠 가중치·중복 완화·새 카테고리 개방으로 구현해 랜덤성과 돌발성을 유지한다.
- 푸시를 도입할 때는 단순 카운트다운 종료보다 사용자의 일상 맥락과 연결되는 일정한 시간대 단서를 우선 검토한다.
- 출시 후 핵심 측정값은 단계별 쿨다운 해제 후 복귀율, 설치 다음 날·그다음 날 복귀율, 복귀 후 완료율이다. 총 플레이 횟수만으로 성공을 판단하지 않는다.
- `0.3.x`에는 사용자에게 노출되지 않는 최소 이벤트 계측을 포함한다. 회차 시작·완료, 쿨다운 화면 노출, 쿨다운 해제 후 복귀를 기록하며 이벤트에는 미션·결과 문구 같은 콘텐츠 원문을 넣지 않는다.
- 이벤트 전송 실패는 플레이·저장·리필 상태를 막지 않는다. 앱인토스 라이브 환경에서만 성과 판단에 사용한다.
